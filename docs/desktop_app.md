# UART Audio Studio：Windows 上位机

独立原生 Windows 应用，深色紧凑侧栏风格，参考 SerialLLMplugin / MCU Serial Bridge 的工程工具布局。无需 VS Code、浏览器、Python 或 ngspice 才能运行发布版。

## 使用

### 1.3.1 歌单保存、转换文件与单曲播放

默认“单曲播放 · 播完停止”。顺序连播、列表循环、单曲循环和随机播放需在播放模式中选择。

固定数据目录为 `%LOCALAPPDATA%\ZipLab\UART Audio Studio`，文件库底部显示实际路径，并可直接打开。`library.json` 保存歌单、原音频路径及转换文件关联；`library.json.bak` 保存最近的有效备份。主文件读取失败会尝试备份并显示提示；两者都损坏时禁止用空歌单覆盖。一个数据目录只允许打开一个播放器实例。

转换完成后，将处理后的 PCM、解算数据、实际 UART 字节和分段时间表一起保存为 `prepared_audio\<配置内容指纹>.npz`，并登记到歌曲记录。重开后同文件、同配置直接读这些结果，不重新跑拟合补偿或编码。旧的 `cache\conversions` 在命中时自动迁移；新的歌单转换文件不受临时缓存自动淘汰限制，会占用磁盘空间。右键歌曲可“打开已转换文件目录”。文件采用无可执行对象的 NPZ 容器，可用 NumPy 读取；向串口发送前由应用按时间表解析。

改变歌曲内容、处理算法、波特率或实际补偿配置时仍需要生成对应的新结果。原 WAV 保持在原位置；转换文件不是原始音乐的搬迁副本。源文件缺失时目前需要重新定位 WAV。

### 1.3 文件库与歌单

右侧“文件库 / 歌单”支持批量导入 WAV、导入文件夹及子文件夹、拖入多个文件或文件夹。相同路径自动合并，导入只读取元数据；选中歌曲才进行转换，已有缓存自动复用。顶部按钮可以收起文件库。

下拉框切换“全部音乐”和命名歌单，`+` 新建，`…` 重命名或删除歌单。右键歌曲可添加到其他歌单或重新定位缺失文件。搜索支持名称和路径，多选后用上下箭头调整顺序。“移除”只移除列表引用；在全部音乐中移除会同时移除所有歌单中的引用，原 WAV 不会删除。

双击歌曲载入并播放；串口未连接时只载入。上一首 / 下一首跟随开始播放时的歌单顺序，支持顺序播放、列表循环、单曲循环和随机播放。手动停止取消自动连播，缺失或不支持的文件自动跳过。歌曲最长10分钟。连播切歌仍需核对或生成转换缓存，会有切歌间隔。

文件库、歌单、最后载入歌曲和播放模式保存在用户本地应用数据目录。重启可恢复最后歌曲，但不会自动播放或打开串口 / 麦克风。列表“缓存”表示至少有一个处理配置的磁盘缓存；实际载入时按当前配置核对。源文件仍保留在原位置，移动后请重新定位。

### 1.2.1 转换缓存

转换结果自动保存为内存缓存和磁盘缓存。同一WAV、同一处理配置再次打开，或切回已转换过的响度/预失真组合时，直接加载结果；重启程序后磁盘缓存仍有效。界面显示“已读取缓存”和耗时。

缓存按WAV内容、处理参数、拟合文件内容、DSP源码指纹及数值库版本核对。修改音频、波特率、补偿、响度、编码器或预失真会使用各自结果；算法变动会使旧结果失效。缓存不包含录音，损坏时自动重新转换，写入失败不影响本次播放。

默认上限为192MiB内存、1GiB磁盘、32个配置结果，自动淘汰最久未使用的转换缓存。磁盘位置为应用数据目录下 `cache/conversions/`。

### 1.2 电路与歌曲预失真研究

新增可开关的歌曲预失真候选，算法为带限二阶特征和短记忆FIR。实时音量采用主信号乘v、二阶补偿乘v²，导出和录音参考保持一致。校正幅度、峰值和UART密度均有界。

当前真实歌曲两段的频谱平衡误差分别改善约0.37dB、0.67dB，录音电平下降约0.5dB。不同乐曲验证未通过，因此全局默认关闭；可以手动开关比较，导入其他WAV时会关闭。电路边沿反馈编码也已实现为实验配置，尚未稳定胜过原编码器。

电路仿真、原始录音、被拒绝的辨识和候选、跨曲验证及硬件校准建议见 [联合优化报告](music_dpd_validation.md)。本轮保持实装电路，未通过仿真结果直接改动Rg或续流。

### 1.1 音量和噼啪声修复

1.1.1 新增“响度：标准 / 增强 / 强劲”，默认强劲。强劲档采用更快恢复的平滑前瞻限幅和更突出的音乐清晰度均衡；同一歌曲片段、相同100%音量、麦克风位置不变时，比1.1版再提高约2.5dB录音带内电平。保持1.1版的偏置0.45、调制幅度0.35和峰值上限，动态会收紧、音色更亮。切换档位后自动重新转换，播放中需要先停止才能切换。

新版默认开启“音乐响度增强”和“连续载波”。前瞻平滑限幅避免一个高峰压低整首音乐；清晰度均衡减少欠缺响应的低频对调制空间的占用，串口调制幅度也已提高。不会改变原曲音高。

Windows 串口改成两个独立 OVERLAPPED 写入请求，提前排队下一包，避免同步逐包发送之间的编码空隙。音乐中的短暂休止保持载波，避免平均驱动反复跳变；文件首尾和音量变化有渐变。静音、0%和停止仍会回到真正停发。连续载波会增加休止时的耗电，可取消勾选。

真实歌曲已在新的听音位置完成成对录放；原始录音、对比参数和结论在 `results/real_song_*`，不依赖单音调参。噼啪声的电子学来源不能仅凭麦克风录音完全分离，未声称所有硬件/声源瞬态已消失。

1. 双击 `UARTAudioStudio.exe`。启动只枚举设备，不自动打开串口或麦克风。
2. 点击“导入 WAV”或将文件拖入窗口。后台自动执行单声道化、16kHz重采样、400–5000Hz带限、内置拟合补偿和8N1编码。支持整数/浮点PCM WAV及中文路径，最长10分钟。
3. 在侧栏选择COM口和波特率，点击“连接串口”，再点“播放”。空格暂停/继续，Esc停止，Ctrl+O导入文件。
4. 音量滑块可在播放中实时调整。增益变化有约10ms渐变；静音和0%在渐变后真正停发，TX空闲为高。音频零样本与UART 0x00不同，应用不会用0x00伪造静音。
5. 信号监视可切换“处理后音频”“UART数字解算”“麦克风实测”。上图为波形，下图为FFT频谱；可平移/缩放并复位。绘图采用保峰显示降采样，FFT和录音保留完整样本。数字解算不是线圈电流实测。
6. 选择麦克风并点击“启用麦克风”。勾选“播放时同步录音”后会保存原始WAV、实际音量变化、播放位置及配置；也可独立录音。
7. 展开“配置与录音拟合”，用最近一次完整、未暂停的同步音乐录音进行宽带拟合。新配置自动保存并重新转换当前音频。需要换曲验证，不应将一次拟合当作通用音质认证。
8. “导出串口数据”保存分段BIN和JSON时间表，保留长休止。仅把BIN串接发送会丢失真正静音间隔。

“运行日志”可展开。默认录音/配置保存在当前用户本地应用数据目录，侧栏可直接打开会话文件夹。设置和麦克风增益不会更改系统默认音频设备；录音是原始幅度，不报告绝对SPL。

## 内置算法

- 测量拟合的正参数M2复阻抗网络，供电气逆传递补偿和拟合先验使用。
- 跨音区多声部音乐验证过的13结点宽带补偿，有限增益FIR，保留原曲音高和时长。
- SciPy robust least_squares音乐幅频辨识、平滑正则、多频谱峰相对频率尺度估计，直接包含在exe中。
- 真实8N1逐位误差反馈，强制起始/停止位，跨块保留误差状态；向量化路径有饱和回退，不将UART当作任意bitstream。
- 低延迟有界发送队列、后台转换/播放/采集、实时音量渐变和真正停发静音。主机进度是估计，不冒充物理TX示波器测量。

## 从源码运行与打包

Windows x64 / Python 3.12：

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-gui.txt
.venv\Scripts\python desktop_app.py
.venv\Scripts\python scripts/build_desktop.py --onefile
```

单文件结果在 `release/single/UARTAudioStudio.exe`；不加 `--onefile` 生成便携目录版。模型和图标在 `desktop_assets/`，重建不需要原始实验结果目录。第三方许可随发布提供；Qt/PySide6为动态库。

## 功能与限制

内置配置对应本项目已测硬件；更换蜂鸣器、限流或麦克风摆位后需要重新测量/拟合。软件不能恢复此类蜂鸣器缺失的低音或实现全频高保真。当前导入格式为PCM WAV，不包含MP3解码。

同步录音拟合要求连续完整播放、至少2秒有声音乐、无ADC削波和采集溢出。中途暂停/停止会保存录音，但这次录音不直接用于自动拟合。USB断开、停止播放或关闭窗口时会尝试取消发送、清空主机队列并保存会话；操作系统队列排空不证明USB硬件FIFO已经清空。

发布版已在本机Windows 11 x64验证，不要求管理员身份运行。单文件版首次启动需要解压内置运行库，可能比便携目录版慢。
